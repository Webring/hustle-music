# Hustle YMPlayer

[English](README.md) · **Русский**

Плеер для тренировок по хастлу. Подбирает треки по темпу (BPM) и играет их через виджет **Яндекс Музыки** или по прямым ссылкам на аудиофайлы. Это статическое веб-приложение: без бэкенда, без аккаунтов, хостить нужны только файлы.

**Демо:** https://webring.github.io/hustle-music/

> Hustle YMPlayer — независимый проект, не связанный с Яндексом. Звук и права остаются на стороне Яндекс Музыки: приложение только подбирает треки и управляет официальным виджетом.

## Возможности

- **Плеер** — интервалы BPM двойными слайдерами (можно несколько), случайный порядок, «Подобрать треки», режим «90 секунд» и повтор трека. Интервалы сохраняются в адресе, например `#bpm=92-118,91-119`, — настройками можно делиться ссылкой.
- **Сигнал «Bring the action»** — звучит при автоматической смене трека (трек закончился или истекли 90 секунд). Ручное переключение — сразу и без сигнала. Стандартный звук встроен; можно выбрать свой файл (хранится в IndexedDB).
- **Треки** — вся база с поиском, сортировкой и фильтром «Все / Лайки / Дизлайки», прослушивание по клику и ссылка на трек в Яндекс Музыке.
- **Мои треки** — добавление ссылок ЯМ вида `/album/…/track/…` и прямых ссылок на аудиофайлы. BPM обязателен; название, артист и теги — по желанию. Можно изменить или удалить свою запись. Трек ЯМ, уже имеющийся в базе, получает ваши BPM и теги без дублирования.
- **Теги** — добавление и изменение у любых треков, поиск и фильтр в списке. В плеере можно выбрать источник и несколько тегов: в подборку попадут треки со всеми выбранными тегами.
- **JSON** — свои треки и теги сохраняются в localStorage. «Скачать JSON» выгружает их одной строкой, без отступов. «Импорт JSON» объединяет файл с текущей библиотекой; одинаковые ID обновляются.
- **Авторизация аудиоссылок** — Bearer, Basic и API key в заголовке. Логины, пароли и токены хранятся в sessionStorage текущей вкладки и не входят в JSON. После переноса библиотеки их нужно указать заново. Сам сервер аудио должен разрешать CORS для адреса приложения и используемых заголовков; приложение загружает файл в память перед воспроизведением.
- **Плавное завершение** — для прямых аудиоссылок, с настройкой от 1 до 30 секунд. Звук затихает к концу трека или к границе режима 90 секунд. У таких треков также доступна перемотка. Затухание работает через Web Audio; громкостью виджета ЯМ приложение управлять не может.
- **Лайки и дизлайки** — лайк просто помечает трек. Дизлайкнутый трек не попадает в плеер, но остаётся в списке. Хранятся в браузере.
- **Репитер** — повтор отрезка A–B для **своих аудиофайлов**. Треки Яндекс Музыки туда не переносятся: в виджете нет перемотки.
- **Вид виджета** — виджет Яндекса можно показать окном в углу, встроить в карточку плеера, оставить только кнопку «Яндекс Музыка» или скрыть полностью (меню палитры → «Виджет Яндекса»).
- **Понятные сообщения об ошибках** — приложение замечает страницу по http, недоступную Яндекс Музыку, трек, который не запускается, отрывки по 30 секунд (нет входа или Плюса) и недоступные треки, и подсказывает, что делать.
- **Тема** — светлая, тёмная или как в системе и пять приглушённых акцентов. Интерфейс адаптивный, работает на телефоне.

## Быстрый старт

Нужен Node.js 22.18+.

```bash
cd app
npm install
npm run dev          # http://localhost:5173
```

| Команда | Что делает |
|---|---|
| `npm run dev` | сервер разработки |
| `npm run build` | статическая сборка в `app/dist` — можно выложить на любой хостинг |
| `npm run build:html` | всё приложение одним файлом `index.html` в корне проекта (~0,9 МБ) |
| `npm run lint` | проверка кода |
| `npm test` | проверки библиотеки, JSON, авторизации и затухания |

Важно:

- Приложение должно открываться по **http(s)**: с хостинга или локального сервера. Если открыть `index.html` как файл (`file://`), интерфейс загрузится, но виджет Яндекса не будет принимать команды.
- Виджет играет только на **безопасной странице**: `localhost` или `https`. По `http://<ip>` он отвечает `STOPPED`. Чтобы проверить на другом устройстве, поднимите dev-сервер по https (см. ниже).
- Полные треки — если в браузере выполнен вход в Яндекс Музыку с подпиской **Плюс**. Без неё — отрывки по 30 секунд. Если браузер блокирует сторонние cookie, виджет может «не узнать» аккаунт.

### Настройки dev-сервера

Необязательные, в `app/.env.local` (в git не попадает):

```
DEV_HOSTS=myhost.local   # дополнительные имена, по которым открывается dev-сервер
DEV_POLL=1               # следить за файлами опросом (сетевые диски, WSL)
```

Если есть `app/.cert/key.pem` и `app/.cert/cert.pem`, dev-сервер запускается по https и слушает `0.0.0.0` — его можно открыть с телефона в той же сети. Сертификаты создайте сами (например, через [mkcert](https://github.com/FiloSottile/mkcert)); в git они не попадают.

## Развёртывание

`.github/workflows/deploy.yml` запускается на каждый push и pull request: установка, lint, сборка. Push в `main` дополнительно публикует `app/dist` на **GitHub Pages**.

Чтобы включить в своём форке: *Settings → Pages → Build and deployment → Source: GitHub Actions*. Сборка использует относительные пути (`base: "./"`), поэтому работает по любому адресу.

## База треков

`app/src/data/tracks.json` — треки с ID из Яндекс Музыки и BPM. Собирается скриптом из списка треков с известным темпом:

```bash
# tracks-bpm.json: [{ "name": "Артист - Название.mp3", "bpm": 118 }, ...]
node scripts/build-ym-db.mjs --source=tracks-bpm.json            # собрать
node scripts/build-ym-db.mjs --source=https://example.com/x.json # список по ссылке
node scripts/build-ym-db.mjs --source=... --limit=40             # пробный прогон
node scripts/build-ym-db.mjs --source=... --refresh              # без кеша поиска
```

Скрипт ищет каждый трек в Яндекс Музыке и сравнивает артиста и название. Ремиксы, live и каверы сопоставляются только с такими же версиями (у них другой темп). Треки, которых нет в каталоге или которые не удалось уверенно сопоставить, попадают в `scripts/ym-unmatched.json` с лучшей догадкой — их можно проверить вручную. Ответы поиска кешируются в `scripts/.cache`.

## Ограничения виджета Яндекс Музыки

Управление идёт через `postMessage` в режиме `display=bandlink-wiki` — это **недокументированная партнёрская интеграция** Яндекса, она может измениться или быть закрыта. Для продакшена нужно согласовать доступ с Яндекс Музыкой.

В протоколе есть только: очередь треков, пауза, продолжить, следующий, предыдущий и события статуса (`PLAYING`, `PAUSED`, `ENDED`…). **Нет перемотки, громкости и текущей позиции** — поэтому для треков ЯМ время на экране считается приложением, затухания нет, а громкость регулируется в самом виджете или системой. Эти ограничения не относятся к прямым аудиоссылкам.

## Устройство проекта

| Путь | Что там |
|---|---|
| `app/src/lib/ym-widget.ts` | протокол виджета Яндекс Музыки (postMessage) |
| `app/src/lib/ym-status.ts` | распознавание проблем с Яндекс Музыкой |
| `app/src/lib/player.ts` | движок плеера: очередь, режим 90 секунд, сигнал, команды виджету |
| `app/src/lib/tracks.ts` | база треков, своя библиотека, теги и JSON |
| `app/src/lib/track-data.ts` | формат библиотеки и проверка данных |
| `app/src/lib/audio-source.ts` | авторизация и загрузка аудиоссылок |
| `app/src/lib/signal.ts` | «Bring the action»: стандартный или свой звук |
| `app/src/lib/repeater.ts` | репитер для своих файлов |
| `app/src/lib/marks.ts` | лайки и дизлайки |
| `app/src/lib/settings.ts` | настройки в localStorage и адресе |
| `app/src/components/ym-widget-frame.tsx` | iframe виджета (один на всё приложение) и режимы показа |
| `app/src/components/ym-notice.tsx` | сообщения об ошибках и подсказки |
| `app/src/pages/` | страницы «Плеер», «Треки» и «Репитер» |
| `scripts/build-ym-db.mjs` | сборка базы треков |

Стек: Vite, React, TypeScript, Tailwind CSS 4, shadcn/ui (Base UI).
